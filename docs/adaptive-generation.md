# 자료량에 따른 생성 개수 조정

## 정책

- `backend/app/services/content_budget.py`에서 실제 텍스트의 문장·줄을 나누고 단어 구성이 같은 내용 및 단어 집합 유사도 0.8 이상의 내용을 합친다.
- 세 종류 미만의 단어 또는 중복 제거 후 15자 미만인 단위는 분량 계산에서 제외한다. 표지·짧은 제목 등에 대한 보수적인 휴리스틱이며, 실제 의미나 사실의 정확성을 판정하지 않는다.
- 고유 단어 문자 수가 100자 미만이면 1개, 800자 미만이면 3개, 2,400자 미만이면 5개, 그 이상이면 8개를 상한으로 삼는다. 독립적으로 남은 단위 수보다 많이 생성하지 않는다. 유효 단위가 없으면 0개다.
- 최대 상한이 확정되면 계산을 멈춘다. `saturated=true`일 때 `unique_units`, `effective_chars`는 전체 집계가 아닌 상한 결정까지 관찰한 값이다.
- 이 수치는 초기 정책값이다. 한국어 동의어나 표현이 다른 의미상 중복은 단어 비교로 완전히 잡을 수 없다. 모델에도 의미 중복을 합치고 개수를 억지로 채우지 않도록 지시한다.

## 적용 범위

- 요약은 자료별로 상한을 산정하여 LLM에 `topic_limit`을 전달한다. 단일 호출과 긴 문서 map-reduce 모두 응답 상한을 적용한다. 긴 문서는 중복 제거한 중간 요점 수로 상한을 추가 제한한다.
- 예상 질문은 실제 선택된 **발표 자료** 근거만 합쳐 산정한다. 질문자 참고자료나 읽지 않은 분량은 상한을 늘리지 않는다. 사용자 요청 수와 자료 상한 중 작은 값을 사용한다.
- 기존 근거 ID·수치 검사와 질문자 간 중복 검사를 유지한다. 고정 템플릿으로 질문을 채우지 않으며, 유효 근거가 없으면 모델 호출 없이 빈 질문 목록을 반환한다.
- `requested_count`는 사용자 요청을 유지하고 `generated_count`와 경고에 실제 결과와 감소 이유를 표시한다. 요약의 생성 상한, 기존 분석 범위, 주제별 출처도 화면에 표시한다.

## 저장 및 호환성

질문 평가 정보는 기존 세션 JSON에 저장한다. 요약의 `assessment`, `warnings`는 기존 coverage JSON 열의 `generation_assessment`, `generation_warnings` 키에 저장하고 API에서는 별도 필드로 복원한다. DB 스키마 변경은 없다. 이전 요약은 읽을 수 있으며, 다음 생성 요청에서 평가 정보가 없는 캐시를 갱신한다. 기존 연습 기록은 당시 결과를 유지한다.

## 검증 한계

자동 테스트는 분량·중복·상한·저장 계약을 검증한다. 실제 모델이 서로 다른 의미의 질문을 얼마나 잘 생성하는지와 문서 사실의 정확성은 별도의 실제 자료 평가가 필요하다. 표시하는 평가는 정확도 점수가 아니다.
