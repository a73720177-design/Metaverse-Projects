### 요 약

본 논문은 발표자료를 근거로 평가자 페르소나별 예상 질문과 후속 대화를 제공하는 LLM 기반 발표 준비 지원 시스템을 제안한다. 시스템은 PDF·PPTX·DOCX 문서와 질문자 설정을 결합하고, bge-m3 임베딩과 BM25를 순위 융합한 검색으로 근거를 선택한 뒤, 개인 PC의 4B급 언어모델로 질문을 생성한다. 소형 모델의 환각을 줄이기 위해 페르소나 특성의 원문 인용 검증과 예상 질문의 근거·용어·수치·중복 필터로 구성된 근거 검증 계층을 설계하였다. 실험 결과 생성 후보의 【측정값】%가 근거 검증 단계에서 제외되었고, 페르소나 3명의 질문 생성에 qwen3:4b 기준 평균 【측정값】초가 소요되었다.

**키워드 :** 발표 준비, 평가자 페르소나, 검색 증강 생성, 환각 억제

### I. 서 론

발표 준비에서는 자료를 설명하는 능력과 함께, 평가자의 관점에서 예상 질문을 검토하고 답변을 수정하는 과정이 필요하다. 범용 대화형 언어모델에 자료를 반복 입력하는 방식은 문서 선택, 질문자 설정, 대화 이력 관리의 부담을 사용자에게 남긴다. 또한 미공개 발표자료를 외부 서버로 보내야 하고, 자료에 없는 수치나 주장을 담은 질문이 생성될 수 있다[3].

검색 증강 생성은 외부 문서의 검색 결과를 생성 과정에 결합하는 접근이다[1]. 본 연구는 이를 발표자료에 적용하고, 질문자 참고자료와 질문별 대화를 연결하는 로컬 시스템을 설계하였다. 또한 개인 PC에서 동작하는 소형 모델의 한계를 고려해, 생성 결과를 원문과 대조하는 근거 검증 계층을 두었다. 기반 모델의 재학습은 연구 범위에 포함하지 않는다.

### II. 시스템 설계 및 구현

그림 1은 로컬 서비스 구성을 나타낸다. React 화면은 Backend를 통해 문서 처리·인증·검색·LLM 기능을 호출한다. LLM Service는 Ollama와 통신하며, Docker Compose가 Web·Backend·LLM·PostgreSQL·Ollama 서비스를 조합한다.

> 【그림 1】 원고의 그림을 그대로 사용

#### 1. 문서와 평가자 페르소나

PDF·PPTX·DOCX에서 텍스트와 구간 정보를 추출하고, 원본 페이지·슬라이드 인덱스를 유지한다. 질문 생성에는 발표자료와 질문자 참고자료를 별도로 전달하여 검토 대상과 평가 관점을 구분한다. 요청은 페르소나당 1~10개 질문을 지원하며, 각 예상 질문에는 독립 conversation_id를 부여하고 사용자 소유권 검사를 적용해 대화 이력을 관리한다. (`backend/app/models/practice.py`)

#### 2. 근거 검증 계층 *(신설)*

소형 모델은 입력에 없는 전문성이나 수치를 생성하기 쉽다. 본 시스템은 추가 LLM 호출 없이 생성 결과를 원문과 대조하는 두 단계 검증을 적용한다.

**(1) 페르소나 특성의 원문 인용 검증.**
- 모델은 질문자 설명과 참고자료로부터 전문 분야·평가 스타일을 생성하고, 특성마다 근거 인용을 함께 제시한다.
- 시스템은 유니코드 정규화(NFKC)와 공백 제거만 거친 인용이 원문에 그대로 존재하는지 검사한다. 문장부호·부정 표현·어순은 보존하므로, 바꿔 쓴 표현이나 여러 구절을 이어 붙인 인용은 통과하지 못한다.
- 유효 문자가 4자 미만인 인용은 기각한다.
- 특성은 사용자 명시·근거 확인·추론·불명·충돌의 다섯 상태로 관리한다. 검증에 실패한 특성은 질문 생성에서 제외하고, 제외 사유(인용 누락, 충돌, 신뢰도 0, 참고자료 변경 등)를 저장해 화면에 안내한다.
- 참고자료 연결이 바뀌면 해당 자료에 기반한 특성을 무효화한다.

(`backend/app/services/persona_service.py`, `models/persona.py`)

**(2) 예상 질문 필터.**
- 모델은 질문과 함께, 그 질문이 근거로 삼은 발표자료 구간의 ID를 출력한다.
- 시스템은 표 1의 규칙을 순서대로 적용해 후보를 채택하거나 기각한다.
- 목표 개수에 못 미치면 기각된 질문 목록을 전달하며 최대 3개씩 다시 생성한다(최대 6회).
- 근거가 부족하면 요청한 개수보다 적은 질문을 제공한다.

(`backend/app/services/practice_service.py`)

**표 1. 예상 질문 필터 규칙**

| 규칙 | 기각 조건 |
|---|---|
| 형식 | 12자 미만, 의문문 아님, 500자 초과, 키릴·일본 문자 포함 |
| 근거 ID | 근거 ID 없음, 또는 발표자료가 아닌 구간을 가리킴 |
| 고유 용어 | 범용어·파일명을 제외하면 근거와 공유하는 용어가 없음 |
| 수치 | 질문 속 수치·단위가 근거 원문에 없음 |
| 중복 | 이미 채택된 질문과 자카드 유사도 0.82 이상 |

#### 3. 검색 및 생성 응답 관리

- **벡터 검색:** bge-m3 임베딩과 pgvector의 코사인 거리 검색을 사용한다. 기본 후보는 12개, 최종 반환 상한은 6개이며, 문서 소유자·모델명·내용 해시 조건으로 검색 대상을 제한한다.
- **어휘 검색과 순위 융합:** 벡터 검색 결과에 BM25 방식의 어휘 검색[4] 결과를 RRF[5]로 결합한다. 임베딩이 놓치기 쉬운 고유명사와 수치를 보완하기 위해서다.
- **폴백:** 색인이 불완전하거나 검색에 실패하면 어휘 기반 발췌로 전환한다.
- **페르소나별 검색 질의:** 질문자 참고자료를 검색 질의에 포함하므로, 페르소나마다 서로 다른 발표 근거가 선택된다.

(`backend/app/services/vector_rag.py`, `rag_service.py`)

LLM 응답은 구조화된 JSON 필드에서 최종 답변을 추출하고, 사고 과정과 프롬프트 지침의 노출을 정제한다. Qwen3의 사고·비사고 모드 구분[2]을 고려해 비사고 모드로 호출한다. 장문 요약·리뷰는 분할·통합(map-reduce) 경로로 처리한다.

#### 4. Windows 배포

Metaverse-Setup.exe는 WSL 2·Docker 준비, DB 마이그레이션, 모델 다운로드를 수행하는 설치 진입점이다. 최초 실행 이후의 추론은 로컬 Ollama로 수행하며, 기본 생성 모델은 qwen3:4b이고 qwen3.5:9b를 선택할 수 있다. Web 포트는 127.0.0.1에만 연결하고, DB·업로드·모델은 Docker 볼륨에 보존한다.

### III. 모의 실험

#### 1. 실험 환경

- 입력: 시연용 발표자료 1건(캠퍼스 분리배출 주제)과 발표 대본 1건
- 페르소나: 기술 검토자, 운영·예산 담당자, 학생 경험 연구자 3명. 각 페르소나에 참고자료 1건 연결
- 요청: 페르소나당 질문 5개를 동일 조건으로 3회 반복 생성
- 측정 PC: 【확인 필요: CPU / RAM / GPU 유무】

배포 패키지의 무결성과 서비스 단위 시험(Backend 243건, LLM 208건 통과)은 별도로 확인하였다.

#### 2. 실험 1: 모델별 생성 시간

표 2는 페르소나 3명의 예상 질문 생성에 걸린 시간과 생성 개수를 나타낸다.

**표 2. 모델별 예상 질문 생성 결과 (3회 평균)**

| 모델 | 전체 시간(s) | 페르소나당(s) | 생성 질문 수 |
|---|---|---|---|
| qwen3:4b | 【측정값】 | 【측정값】 | 【측정값】/15 |
| qwen3.5:9b | 【측정값】 | 【측정값】 | 【측정값】/15 |

> 해석 문장 예시: "9B 모델은 4B 대비 생성 시간이 【측정값】배 증가하였으나, 필터를 통과한 질문 수는 【측정값】개 차이를 보였다."

#### 3. 실험 2: 근거 검증 필터의 기각 분포

모델이 출력한 후보 질문마다 처음 위반한 규칙을 기록하였다. 표 3은 규칙별 기각 비율을 나타낸다. 후보 하나는 처음 위반한 규칙 하나에만 집계하였다.

**표 3. 필터 단계별 기각 비율 (qwen3:4b, 3회)**

| 단계 | 기각 수 | 비율(전체 후보 대비) |
|---|---|---|
| 형식 | 【측정값】 | 【측정값】% |
| 근거 ID | 【측정값】 | 【측정값】% |
| 고유 용어 | 【측정값】 | 【측정값】% |
| 수치 | 【측정값】 | 【측정값】% |
| 중복 | 【측정값】 | 【측정값】% |
| 최종 채택 | 【측정값】 | 【측정값】% |

이어서 채택된 질문과 기각된 질문을 저자가 직접 검토해, 발표자료에 없는 내용을 주장하는 질문의 비율을 비교하였다. 그 비율은 채택군 【측정값】%, 기각군 【측정값】%였다.

> 해석 문장 예시: "기각 후보의 다수는 【가장 큰 규칙】 단계에서 제외되었으며, 이는 소형 모델이 근거 구간과 무관한 일반 질문을 자주 생성함을 보여 준다."

> **분량 조정:** 2쪽을 넘으면 표 2를 본문 한 문장으로 줄이고 표 3만 남기세요. 표 3을 막대그래프(그림 2)로 바꿔도 됩니다.

### IV. 결 론

본 논문에서는 문서 근거, 평가자 페르소나, 질문별 대화를 연결하고 개인 PC에서 동작하는 발표 준비 지원 시스템을 구현하였다. 또한 페르소나 특성의 원문 인용 검증과 예상 질문 필터로 구성된 근거 검증 계층을 설계하였다. 실험에서는 생성 후보의 【측정값】%가 근거 검증 단계에서 제외됨을 확인하였다.

다만 인용 검증은 문자 일치를 확인할 뿐, 인용이 특성을 의미적으로 뒷받침하는지는 판단하지 않는다. 또한 질문 생성은 선택된 발췌만 사용하며, 시각 정보 분석은 VLM이 동작하는 환경에서만 활성화된다. 새로운 PC에서의 설치 성공률과 사용자 대상 교육 효과는 후속 연구에서 검증할 예정이다.
