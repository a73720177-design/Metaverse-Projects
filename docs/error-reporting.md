# 프론트 오류 확인

화면 오른쪽 아래 **오류 · 상태**에서 최근 오류 20개를 확인합니다. 로그인 전에도 사용할 수 있으며 오류가 발생하면 패널이 열립니다. 기록은 현재 탭의 메모리에만 남고 새로고침 시 초기화됩니다.

- 오류 메시지와 확인 방법을 먼저 표시합니다.
- **개발 확인용 상세 정보**에서 HTTP 상태, 오류 코드, 요청 방식/경로, 시각, 요청 ID, 입력 오류 위치를 확인합니다.
- **오류 정보 복사**로 서버 로그와 대조할 수 있는 진단 정보를 복사합니다. 브라우저가 자동 복사를 지원하지 않으면 선택해서 복사할 텍스트를 보여줍니다.
- **서비스 상태 확인**에서 백엔드, DB 스키마, LLM 연결을 조회합니다. 조회만 수행하며 DB 변경이나 재시작은 하지 않습니다.

## 처리 범위

| 상황 | 표시/동작 |
| --- | --- |
| 로그인 실패 / 중복 가입 / 요청 제한 | 실패 이유, 401/409/429, 가능하면 Retry-After 대기 시간 |
| 인증된 요청의 401 | 로그인 화면으로 전환하며 오류 기록 유지 |
| 필수 값, 길이, 형식, 범위 오류 | 항목 이름과 조건; 서버 422의 위치/타입 |
| 파일 형식, 빈 파일, 크기 제한 | 업로드 전 검사 및 서버 400/413/415 |
| 권한 부족, 삭제된 자료, 요청 충돌 | 403/404/409와 요청 경로 |
| DB 연결/읽기 전용/컬럼 누락, 파일 저장소 장애 | 구분된 오류 코드와 확인 방법 |
| 서버 응답 모델 불일치 | response_validation_error와 응답 필드 위치 |
| 처리되지 않은 서버 예외 | 안전한 500 JSON, 예외 종류, 요청 ID |
| 서버 미실행, 오프라인, CORS/프록시 문제 | 연결 실패 안내; 브라우저가 제공하지 않는 원인은 단정하지 않음 |
| 요청 지연, 잘못된 JSON | 시간 초과 또는 응답 형식 오류 |
| 채팅 생성/저장 오류, 불완전한 스트림 | SSE 오류 코드, 요청 ID, 완료 전 연결 종료 안내 |
| 브라우저 저장 실패, 렌더링 예외, 처리되지 않은 Promise | 공통 패널 및 렌더링 실패 복구 화면 |

명시적인 요청 취소는 오류로 기록하지 않습니다. 변경 요청을 자동 재시도하지 않습니다. 일반 요청 제한 시간은 30초, 업로드/요약은 3분, 예상 질문/채팅은 5분이며 채팅은 수신이 60초간 없을 때에도 중단합니다.

요청 본문·인증 헤더·토큰·비밀번호·검증 실패 입력 원문은 진단 기록에 포함하지 않습니다. 쿼리 문자열도 경로에서 제외합니다. 예외 상세 스택은 서버 로그에서 요청 ID로 확인합니다.

## 적용 및 검증

백엔드 코드 변경 후 실행 중인 CMD에서 서버를 재시작합니다. 프론트는 Vite의 변경 반영 또는 브라우저 새로고침으로 적용합니다. 기존 백엔드가 실행 중이면 요청 ID가 표시되지 않을 수 있습니다.

- 프론트: `npm test`, `npm run build`
- 백엔드: 프로젝트 가상환경으로 `tests/test_error_diagnostics.py`, `tests/test_auth.py`, `tests/test_main.py`, `tests/test_resume_regressions.py` 실행
- 백엔드 테스트는 `REPOSITORY_MODE=memory`, `RAG_MODE=lexical`, `DB_AUTO_CREATE=false`와 기본 CORS 설정을 사용합니다. 실제 DB를 변경하지 않습니다.
