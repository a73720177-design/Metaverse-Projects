# RAG / 청킹 품질 보강

## 검색 흐름

채팅은 연결 문서를 소유자 범위에서 조회한 뒤, 현재 모델·내용 해시에 맞는
유효한 벡터로 검색한다. 일부 색인이 누락되어도 다른 문서의 벡터 검색을
유지한다. 검색 오류 또는 벡터 결과가 없으면 BM25 방식의 키워드 검색으로 전환한다.
벡터 결과가 있을 때에도 각 문서의 키워드 검색 결과를 교차 배치한다.
최종 근거에는 파일·원본 페이지 정보와 전역 `[근거 N]` 번호를 붙인다.

## 이번 변경

- 검색 시 기본 700자, 겹침 최대 100자로 청킹한다. 문장·줄 경계를
  우선하고 긴 단일 문장도 겹침을 유지한다. 어떤 경우에도 크기 상한을 넘지 않는다.
- 원문을 슬라이스하여 줄바꿈, 표의 탭, 소수점, 버전 문자열을 유지한다.
- 벡터로 찾은 페이지를 다시 청킹하고 질문과 관련된 부분을 우선한다.
  키워드가 일치하지 않는 의미 검색 결과도 최대 한 청크를 유지한다.
- 문서 전체의 키워드 결과도 함께 넣어 정확한 코드·이름·수치의 누락을 보완한다.
  같은 문서·페이지·본문의 완전 중복을 제거한다.
- 근거는 관련도순을 유지한다. 다중 문서 예산으로 잘릴 때 낮은 페이지 번호가
  높은 관련도의 근거보다 먼저 들어가던 문제를 수정했다.
- 벡터 거리 기준을 후보 수 제한 전에 적용한다.
- 명시적인 후속 질문만 이전 사용자 질문을 검색어에 추가한다.
  이는 규칙 기반 판별이며 모든 모호한 후속 표현을 해석하지는 않는다.
- 청크 캐시는 본문뿐 아니라 섹션 내용·페이지·출처 정보 변경도 반영한다.

## 검증과 운영 범위

회귀 테스트는 긴 페이지 끝의 근거, 키워드·벡터 혼합, 출처 매핑,
청크 크기·겹침, 숫자·줄바꿈 보존, 질문 전환과 캐시 갱신을 검증한다.
로컬 테스트는 CI와 같은 `REPOSITORY_MODE=memory`,
`OBJECT_STORAGE_MODE=local`, `DB_AUTO_CREATE=false` 환경을 사용하며 벡터 단위
테스트는 검색 결과 또는 임베딩 클라이언트를 대체한다. `RAG_MODE`는 기본값
`vector`를 그대로 쓴다.

이번 변경은 검색 시점에 적용되므로 기존 문서 재업로드나 재색인은 필요 없다.
DB의 벡터 저장 단위는 여전히 파서의 섹션(주로 페이지)이다. 임베딩 API의
`truncate=true`도 유지되므로 매우 긴 페이지의 의미 표현이 완전하다는 보장은
없다. 하위 청크별 벡터 색인으로 전환하려면 원본 페이지와 검색 청크를 분리하는
스키마 및 기존 자료 재색인이 필요하다.

운영 PostgreSQL·임베딩 서버의 연결 및 색인 완전성, 실제 질문 세트에 대한
검색 적중률과 답변 정확도는 별도의 실환경 검증 대상이다.
