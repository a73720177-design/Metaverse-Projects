# LLM 응답 품질 보강 — 2026-09-16

## 수정한 문제

- **질문 의도:** 채팅에서 장점·수정 제안을 항상 요구하던 지침을 평가 요청에만 적용한다. 요약·설명·비교는 해당 요청에 먼저 답한다.
- **근거 사용:** 제공된 인용 번호만 사용하고, 검색 결과에 없는 내용을 문서 전체에 없다고 단정하지 않도록 한다. 문서에 적힌 주장과 실제 뒷받침 증거를 구분하는 리뷰 판정 기준을 추가했다.
- **실제 생성 경로:** 예상 질문 빌더에 관점 다양성, 단위·약어 보존, 유효한 발표 근거 ID 연결 지침을 적용했다.
- **문서 보존:** 채팅 길이 계산과 렌더링에서 동일한 구간 텍스트·라벨을 사용한다. 래퍼를 포함한 최종 프롬프트 길이를 검사한다. 문서 구간을 실제 입력으로 쓰면서 `full_text` 길이만 검사하던 요약·리뷰 분기도 수정했다.
- **요약·리뷰 파이프라인:** 짧은 문서 요약에도 원래 구간 번호를 전달한다. map/reduce에도 한국어, 자료 내 명령 무시, 시각 분석의 불확실성 보존 규칙을 적용한다. 표본 추출한 경우 최종 생성 모델에도 한계를 알린다. 요약 reduce에는 원문이 없으므로 원문 인용을 새로 만들지 않도록 한다.
- **페르소나:** 근거가 부족하면 특성 개수를 채우지 않아도 된다. 긴 문서 처리에서도 `unknown`·`conflicting` 특성을 제외하는 공통 렌더러를 쓴다.
- **모델 호출:** vLLM은 설정된 `VLLM_MODEL`을 우선 사용한다. 비동기 스트리밍의 반복 억제 설정을 기존 일반 호출과 맞췄다.

## 출력 예산

JSON의 근거·메타데이터까지 담을 수 있도록 최대 출력 토큰을 늘렸다. 실제 출력 길이는 프롬프트의 간결성 지침으로 제한한다.

| 작업 | 이전 | 변경 |
| --- | ---: | ---: |
| 페르소나 | 512 | 1024 |
| 리뷰 reduce | 1024 | 2048 |
| 간결한 요약 | 512 | 1024 |
| 상세 요약 | 1024 | 2048 |
| 개요 요약 | 768 | 1536 |

긴 응답은 생성 시간이 늘어날 수 있다. 채팅 컨텍스트 예산은 기존 `LLM_APPROX_CHARS_PER_TOKEN` 기반 추정이며 실제 모델 토크나이저로 계산한 값은 아니다.

## 검증과 남은 측정

회귀 테스트는 구간 번호 보존, 실제 프롬프트 길이, 긴 구간의 map/reduce 분기, 표본 분석 안내, 모델 선택 및 스트리밍 설정을 검증한다. Backend 계약 테스트로 기존 요청·응답 호환성도 확인한다.

실제 Ollama/vLLM 추론을 통한 답변 품질·지연 시간 비교는 수행하지 않았다. 배포 모델에서는 동일 자료로 요약·설명·비교·평가·근거 없는 질문을 반복 실행하여 인용 정확성, 수치·단위 보존, 중복 질문, JSON 완결성과 응답 시간을 비교해야 한다. 프롬프트 지침만으로 의미적 정확성이 보장되지는 않는다.
