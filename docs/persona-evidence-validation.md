# 페르소나와 발표 평가의 근거 검증

## 적용된 동작

- 페르소나 생성·수정은 참고자료별로 3,000자 예산을 나누며, 전체 구간에서 개요와 설명에 관련된 발췌를 선택한다. 긴 첫 파일이 뒤 파일의 예산을 모두 사용하는 것을 방지한다.
- 특성의 evidence.summary는 description 또는 실제 전달한 reference_context에 공백을 정규화한 뒤 포함되어야 한다. 유효한 인용이 없으면 unknown, confidence=0으로 바꾸고 평가 프롬프트에서 제외한다. 참고자료만으로 뒷받침되는 user_stated 특성은 inferred로 낮춘다. 인용 일치만 검사하며 특성의 의미적 타당성을 보증하지 않는다.
- PERSONA_FALLBACK_LOCAL=true에서는 역할을 `기본 평가자 (로컬 모드)`로 표시한다. 설명을 직접 평가 관점으로 사용하고 전문 분야를 임의로 채우지 않는다. 경고는 API·질문자 선택 화면·예상 질문 결과에 표시된다.
- 예상 질문의 비벡터 경로는 짧은 문서를 예산 안에서 그대로 사용한다. 긴 문서는 전체 구간을 탐색해 개요와 관련 구간을 최대 8개 발췌한다. 긴 단일 페이지의 뒤쪽도 후보에 포함한다. coverage는 같은 페이지의 여러 발췌를 중복 집계하지 않으며, 생략 시 경고를 표시한다.
- 리뷰의 주장 인용과 장점·보완점 인용에 대해 파일명, 문서 ID, 구간, 원문 인용을 검사한다. 가짜 인용은 제거하고 인용이 없는 주장이나 인용에 없는 수치를 포함한 주장은 insufficient_evidence로 낮춘다. 인용이 없거나 인용에 없는 수치를 포함한 피드백은 평가를 보류한다.
- 긴 문서 리뷰의 map 단계에서도 인용이 해당 구간에 존재하는지 검사하여 가짜 인용을 최종 종합의 입력에서 제외한다.
- feedback에 positive_sources, negative_sources, verification_warnings, source_check_performed를 포함한다. 기존 feedback JSON 열에 함께 저장하므로 DB 스키마 변경은 필요 없다. 화면에는 장점·보완점의 인용과 검증 결과를 표시한다.

## 범위와 운영

이 검증은 인용의 원문 일치와 일부 수치·중복을 확인한다. 인용이 판단을 논리적으로 뒷받침하는지, 문서 자체의 주장이 사실인지까지 검증하지 않는다. 외부 검색·사실 확인은 추가하지 않았다. confidence는 검증된 확률이 아니다.

예상 질문은 여전히 제한된 발췌에 기반한다. 리뷰 전체 구간 분석이 필요하면 기존 `REVIEW_ANALYSIS_MODE=full` 설정을 사용한다. 이 모드는 호출 한도를 초과하면 오류를 반환하며 몰래 표본 분석으로 바꾸지 않는다. 모델 호출 수와 처리 시간이 늘어난다.

기존 페르소나는 편집 후 저장해야 새 특성 검증이 적용된다. 기존 리뷰는 자동 재작성하지 않으며 화면에 인용 검증 정보가 없음을 알린다. 새 검증이 필요한 리뷰는 다시 생성한다. 백엔드와 LLM 서비스를 함께 업데이트해야 피드백 인용이 전달된다. 이전 LLM 서비스가 인용을 보내지 않으면 백엔드는 해당 평가를 보류한다.

## 회귀 검증

`backend/tests/test_evidence_validation.py`에서 가짜 인용·잘못된 파일/페이지/문서 ID, 근거 밖 수치, 피드백 보류와 저장, 페르소나 생성·수정, 뒤쪽 참고자료 배분, 관련 페이지 및 긴 페이지 뒤쪽 선택을 검증한다. `llm-service/tests/test_review_pipeline.py`에서는 map 단계의 가짜 인용 제거를 검증한다.
